# Changelog

Every shipped change gets an entry here. Releases are tagged.

## Unreleased
- The workspace and CI.
- The model port, a scripted fake model, and the contract every model adapter must keep.
- A fake MCP server for dev and tests, over stdio or HTTP.
- The decision slot: should the persona react to something nobody asked about, and how. The first decider is the accepted reaction rules.
- A bare "thanks" or "ok" gets no reply message, unless it answers her question.
- Step 2 checks, each a yes with conditions: pi-ai as the model layer in the webview, pi-durable as the durable engine in the webview, and starting local MCP servers on Windows. See docs/spikes.md.
- Data will live in IndexedDB through pi-durable's store, with a check for each drawback. See docs/design.md.
- The native shell (step 3): the Windows exe that holds Familiar's app folder, windows, tray and settings. Keys are typed in their own Settings window and no page can read one back. Data leaves only for places the person approved, and only programs they approved start, each asked through Windows' own dialog. Every promise has a check on a Windows runner, 70 in all, and each must pass. See docs/shell-design.md.
- The model layer (step 4): one adapter over pi-ai for OpenAI-compatible endpoints, Anthropic and Gemini, presets for OpenRouter, OpenAI, Anthropic, Gemini, Ollama, LM Studio and any other OpenAI-compatible address, the model list with prices, Settings' Test, caps kept as a reservation ledger so no call can spend past a cap, and bounded retries only when the endpoint says nothing was done. Keys stay in the exe: every call carries a placeholder. Recorded replies of all three APIs pass the model contract in Node and in the real app on the Windows runner. See docs/model-design.md.
- The turn loop and its journal (step 5), on pi-durable with its IndexedDB store, every write strict: a turn killed at any step goes on when the app opens again, without doing anything twice. A tool with an outside effect that was cut off becomes a question instead of running again, consent cards and wake times survive a restart, a turn asks after 8 tool steps, at most 8 tool calls of one reply and 32 of one turn ever run, and a cap pauses a turn instead of failing it. Every tool call passes one consent gate that asks unless a tool is a listed built-in, and each turn keeps its own budget and spend until it's finished. Cap reservations are kept in the journal too. Kill tests for every kind of step pass in Node and in headless Chromium, and so does pi-durable's storage suite. See docs/turn-design.md.
- Character cards (step 6): V1, V2 and V3 cards from JSON or PNG, read into one form with a limit on everything, and accepted only if they write back out and read again. Lorebooks with keyword, selective and always-on entries, their order and a budget; a card's regex keys run on Familiar's own linear-time matcher, which agrees with JavaScript's on its subset and can't be made to hang. Macros, the prompt in the planned order within a budget, and a plain helper for when there's no card. Her traits (sociability, closeness, lively hours, interests) read from the card by her own model in one call, each reason quoted from a single field of the card, a word list over the tags before and instead, and the person's own choices never overwritten. Card text never goes into warnings or logs. See docs/cards-design.md.
- The MCP client (step 7): local servers started through the exe, and remote servers through the guarded fetch over Streamable HTTP, all with the official MCP SDK. Legacy SSE servers are refused for now, in plain words. Add one by pasting the block from its README or by a form. Its secrets go straight to Credential Manager, the paste isn't kept, and the saved setup holds none of them; a setting that looks like a key is only ever a secret. Literal copies of a secret are blanked from a server's output; a copy the server escapes in JSON isn't yet, which the pre-release native pass fixes. Test says what went wrong in plain words. An `npx`, `uvx` or `docker run` with no pinned version is flagged, with how to pin it. Each server has one owner that answers every call exactly once: a result, Stop, a time limit, or interrupted when the server crashed under it, which is never sent again. A crashed server restarts twice in ten minutes, then shows as down with its last output. A tool that changes goes back to ask, and so does every tool of a server whose command or version changes; a call made for the tool as it was is never sent. A server's answers are marked as outside content. See docs/mcp-design.md.
